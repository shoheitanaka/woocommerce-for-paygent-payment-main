# 試験環境ツールを使った他の決済手段のテスト

## やること

コンビニ決済・ATM決済（仮想口座）・銀行ネットは、お客様が実際にコンビニ店頭やATM、インターネットバンキングで
支払いを完了させる決済手段です。テスト環境では実際の入金は発生しないため、ペイジェントが提供する
**「試験環境ツール」**を使って、入金が完了した状態を擬似的に作り出してテストします。

## 事前準備：試験環境ツールへのアクセス

試験環境ツールへのアクセスには、通常のログインではなく**クライアント証明書による認証**が必要です。
証明書のインストール方法は、以下の資料をご確認ください。

- 試験環境ツールアクセス設定マニュアル（Mac版 / Windows版）

これらの資料は、ペイジェント社の加盟店管理者サイト（[https://portal.paygent.co.jp/n/manage-m/login.html](https://portal.paygent.co.jp/n/manage-m/login.html)）にログインし、
「マニュアル／仕様書 ＞ 試験環境の利用方法」からダウンロードできます。

証明書の準備ができたら、以下のURLにアクセスします。

```
https://sandbox.paygent.co.jp/testtool/statusupdatesearch
```

## 手順

### 1. テストしたい注文の「決済ID」を確認する

まず、テストしたい注文を実際にサイトのチェックアウト画面から作成しておきます（コンビニ決済やATM決済で注文を確定させます）。

コンビニ決済・ATM決済の場合、この「決済ID」は WooCommerce の注文詳細画面の「Transaction ID」欄に記録されています。
（注文メモには店舗名や支払期限などは記録されますが、決済IDそのものは含まれません。）

「Transaction ID」欄が空、または確認できない場合は、ペイジェント社の加盟店管理者サイト（[https://portal.paygent.co.jp/n/manage-m/login.html](https://portal.paygent.co.jp/n/manage-m/login.html)）にログインして確認してください。
決済日時や注文金額などを手がかりに、対象の注文を検索できます。

### 2. 決済検索画面で情報を入力する

試験環境ツールにアクセスすると【決済検索画面】が表示されます。以下の4項目をすべて入力し、「検索」をクリックします。

| 項目名 | 入力する内容 |
| --- | --- |
| マーチャントID | [基本設定](03-basic-settings.md) の「試験環境」に入力したマーチャントID |
| マーチャント接続ID | 同じく「試験環境」の接続ID |
| マーチャント接続パスワード | 同じく「試験環境」の接続パスワード |
| 決済ID | 手順1で確認した取引ID |

検索に成功すると、【ステイタス変更画面】に切り替わり、その注文で変更可能なステータスと入力項目が表示されます。

### 3. ステータスを更新する（決済手段別）

決済手段によって表示される項目が多少異なりますが、基本的には「入金があった日時」などを入力して「実行」を押すだけです。

#### コンビニ決済の場合

「申込済」の状態から「消込済」（入金完了）に変更します。

- **入金日時**: 入力した日時が、お客様が実際にコンビニで支払った日時として登録されます。
- コンビニの種類によっては「コンビニ企業CD」の指定が必要になる場合があります。画面の指示に従って選択してください。

「実行」をクリックすると、「正常終了しました。」というメッセージが表示され、少し待つとWooCommerce側の注文ステータスも自動的に更新されます。

> **支払い期限切れのテストをしたい場合**: 「支払期限切」への変更も、実際の期限日を待たずに操作できます。期限切れ時にお客様や自分自身にどのような表示がされるか、あわせて確認しておくとよいでしょう。

#### ATM決済（仮想口座）の場合

「申込済」の状態から「消込済」に変更します。

- **金融機関コード**: 入力した値が、支払いに使われた金融機関コードとして登録されます（例: `9900` = ゆうちょ銀行、`0010` = りそな銀行）。
- **入金日時**: 入力した日時が支払日時として登録されます。

> **注意**: [注文の管理](08-order-management.md) でも触れている通り、執筆時点のバージョンでは**ATM決済は入金通知を受け取ってもWooCommerce側の注文ステータスが自動更新されません**。ここでの操作はあくまでペイジェント側の決済ステータスを「消込済」にするものです。WooCommerce側の注文ステータスは、加盟店管理者サイトで入金を確認した上で手動で更新する運用になります。

#### 銀行ネットの場合

考え方はATM決済と同じです。「申込済」から「消込済」に変更する際に、金融機関コードと入金日時を入力します。

> 銀行ネットでは、金融機関コードの先頭が「D」で始まるもの（三菱UFJ銀行・楽天銀行など、金融機関と直接接続しているもの）は試験環境ツールでは更新できません。テストの際は、それ以外の金融機関コード（例: `9900` ゆうちょ銀行、`0010` りそな銀行）を利用してください。

### 4. WooCommerce側の反映を確認する

**コンビニ決済・銀行ネット**は、試験環境ツールでステータスを更新すると、ペイジェントからサイトへ自動的に通知が送られ、注文ステータスが更新されます。
[注文の管理](08-order-management.md) の手順で注文詳細画面を開き、注文メモに入金完了の記録が追加されていることを確認しましょう。

反映まで数秒〜数十秒かかることがあります。すぐに反映されない場合は、少し時間を置いてから注文詳細画面を再読み込みしてください。

**ATM決済**は前述の通り自動反映されないため、加盟店管理者サイトで消込済になっていることを確認したうえで、WooCommerce側の注文ステータスを手動で更新してください。

## このテストで確認できること

- コンビニ決済・銀行ネットで、入金完了後に注文ステータスが自動的に更新されるか
- お客様への注文完了メールなどが、入金確認のタイミングで正しく送信されるか
- 支払期限切れになった場合の注文の扱い（キャンセル処理が必要か等、運用ルールの確認）
- ATM決済で、手動更新の運用フローに問題がないか

## ポイント・注意

- クレジットカード決済は、その場でオーソリ・売上処理が行われるため、この試験環境ツールでは操作できません。[クレジットカード決済の詳しいテスト方法](10-testing-credit-card.md) のテスト用カード番号を使ってテストしてください。
- **キャリア決済・電子マネー決済もこの試験環境ツールでは操作できませんが、クレジットカード決済のテスト方法（カード番号を入力する方式）はそのまま流用できません。** キャリア決済はお客様がキャリア（au/docomo/ソフトバンク等）の認証画面にリダイレクトされる仕組みのため、テスト方法が異なります。テスト方法の詳細は、ペイジェント社の加盟店管理者サイトで提供される決済手段別の資料をご確認ください。
- 試験環境ツールの画面項目は、契約しているコンビニの種類（接続タイプ）によって多少異なる場合があります。表示された画面の案内文に従って入力してください。

一通りのテストが完了したら、いよいよ [本番環境への切り替え](12-going-live.md) に進みましょう。
