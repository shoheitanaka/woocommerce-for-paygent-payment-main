# クレジットカード決済の詳しいテスト方法

## やること

クレジットカード決済は、ペイジェントが提供する**テスト専用のカード番号**を使うことで、実際のお金を動かさずに
「成功」「失敗」「3Dセキュア認証」など、さまざまなパターンをその場で確認できます。この章では、主要なテストパターンを
一通り試せるように、具体的なカード番号・名義人・パスワードの一覧を紹介します。

> これらの番号は [基本設定（加盟店情報の入力）](03-basic-settings.md) で「試験環境」にチェックが入っている状態でのみ使用できます。本番環境では動作しません。

## 1. 基本パターン：決済が成功する／失敗するテスト

まずは、決済がそのまま成功するケースと、失敗するケースを試してみましょう。カード番号の下4桁によって結果が変わります。
有効期限は「試験当月から20年先まで」の範囲であれば任意の日付でかまいません。セキュリティコードも3〜4桁の任意の数字で構いません。

### 決済（オーソリ）が成功するカード番号

以下の番号で注文すると、決済はいったん正常に成功します。ただし「取消NG」のカードは、後から
[注文の管理](08-order-management.md) で紹介した返金・キャンセル操作を行うと、そこで失敗するように作られています。
返金操作のテストをしたい場合は、あえてこの「取消NG」の番号を使ってみましょう。

| ブランド | 決済が成功し、返金・取消も成功する番号 | 決済は成功するが、返金・取消は失敗する番号（取消NG） |
| --- | --- | --- |
| VISA | 4708-2241-9240-1234 | 4708-2241-9240-2601 |
| Master | 5251-4593-5851-1345 | 5251-4593-5851-2612 |
| JCB | 3527-4572-6426-1456 | 3527-4572-6426-2630 |
| AMEX | 3765-4593-5851-1567 | 3765-4593-5851-2631 |
| DINERS | 3600-3075-4305-1678 | 3600-3075-4305-2650 |

### 決済（オーソリ）自体が失敗するカード番号

以下の番号を使うと、注文時点で決済が失敗します。エラーの原因（レスポンス）が異なる2パターンが用意されています。

| ブランド | オーソリNG（お客様のカードが拒否されたケース） | オーソリタイムアウト（通信タイムアウトが起きたケース） |
| --- | --- | --- |
| VISA | 4708-2241-9240-8102 | 4708-2241-9240-9123 |
| Master | 5251-4593-5851-8103 | 5251-4593-5851-9234 |
| JCB | 3527-4572-6426-8112 | 3527-4572-6426-9345 |
| AMEX | 3765-4593-5851-8142 | 3765-4593-5851-9456 |
| DINERS | 3600-3075-4305-8160 | 3600-3075-4305-9567 |

### このテストで確認できること

- 決済成功時に、注文が正しく「処理中」または「完了」ステータスになるか
- 決済失敗時に、お客様にきちんとエラーメッセージが表示されるか（注文が変な状態のまま残らないか）
- 「取消NG」のカードで決済した注文を返金操作すると、エラーになる様子を確認する（実際の運用でカードが失効している等の理由で返金に失敗するケースの練習になります）

## 2. 3Dセキュア2.0のテスト

[クレジットカード決済の設定](04-credit-card.md) で「3D セキュア 2.0」を有効にしている場合、決済の認証パターンもテストできます。
3Dセキュア2.0には大きく2つの認証方式があります。

- **リスクベース認証（フリクションレス）**: お客様に追加の入力を求めず、裏側で自動的に認証が完了する方式
- **チャレンジ認証**: お客様に追加のパスワード入力などを求める、認証画面が表示される方式

どちらのパターンが発生するかは、カードの**名義人（カード名義）**にテスト専用の値を入力することで制御できます。

### リスクベース認証（認証画面が表示されないパターン）のテスト

カード番号は「1. 基本パターン」の**決済が成功する番号**を使い、カード名義人欄に以下の値を入力してください。

| ブランド | 名義人 | 結果 |
| --- | --- | --- |
| VISA | BAVYA | 認証成功（そのまま決済が進みます） |
| VISA | BAVAA | 認証成功（Attempt扱い。カード発行会社側で完全な認証ができなかったが、決済は進みます） |
| VISA | BAVNA | 認証失敗（決済がエラーになります） |
| VISA | BAVUA | 認証成功（Attempt扱い） |
| VISA | BAVRA | 認証失敗（決済がエラーになります） |
| MasterCard | BAMYA | 認証成功 |
| MasterCard | BAMAA | 認証成功（Attempt扱い） |
| MasterCard | BAMNA | 認証失敗 |
| MasterCard | BAMUA | 認証成功（Attempt扱い） |
| MasterCard | BAMRA | 認証失敗 |
| JCB | BAJYA | 認証成功 |
| JCB | BAJAA | 認証成功（Attempt扱い） |
| JCB | BAJUA | 認証成功（Attempt扱い） |
| JCB | BAJRA | 認証失敗 |
| AMEX | BAAYA | 認証成功 |
| AMEX | BAANA | 認証失敗 |
| AMEX | BAAAA | 認証成功（Attempt扱い） |
| AMEX | BAAUA | 認証成功（Attempt扱い） |
| AMEX | BAARA | 認証失敗 |

> 名義人の名付けルールは共通しています。先頭の「BA」の後に**ブランドを表す文字**（V=VISA、M=MasterCard、J=JCB、A=AMEX）、続けて**認証結果を表す文字**（Y=成功、A・U=成功だがAttempt扱い、N・R=失敗）が入っています。覚えておくと応用が利きます。

> **重要**: 「Attempt扱い」の2パターン（名義人末尾が`A`・`U`のもの）は、[クレジットカード決済の設定](04-credit-card.md) で紹介した以下のオプションの**設定次第で結果が変わります**。初期状態（未設定）のままでは、どちらも決済がキャンセルされるのが正しい挙動です。
>
> - 末尾`A`（例: `BAVAA`）のパターン: 「3Dセキュア非対応カード許可」（`no_tds_card`）が**有効**の場合のみ決済が成功します。無効（初期値）のままだと意図的にキャンセルされます。
> - 末尾`U`（例: `BAVUA`）のパターン: 「与信あり要注意時の続行可否」（`attempt`）が**有効**の場合のみ決済が成功し、続行時は設定した通知先メールアドレスにアテンプト通知が送信されます。無効（初期値）のままだと決済不可になります。
>
> これらのオプションを有効にすると、カード発行会社側で完全な本人認証ができなかった決済でも売上を確定できるようになりますが、その分**チャージバック（不正利用による支払い取消）のリスクを加盟店様が負う**ことになります。有効にするかどうかは、リスク許容度に応じて判断してください。

以下のような、通信エラーを再現するための特殊な名義人も用意されています。

| 名義人 | 再現されるシナリオ |
| --- | --- |
| BBErrABAB | 認証サーバー（ActiveServer）からのエラー応答 |
| BCErrTimeOut | 認証システムでの取引タイムアウト |
| BDErrInvalidInput | 認証システムからの報告電文チェックエラー |

> **注意**: これらの名義人には英大文字・小文字が混在しています。決済フォームによっては入力値が自動的に大文字に変換されてしまい、名義人が意図した値と異なってしまうことがあります。正しく動作しない場合は、入力欄が大文字変換されていないか確認してください。また、この3パターンの実際の決済結果（成功扱いになるか失敗になるか）は環境によって異なる可能性があるため、次に紹介するチャレンジ認証側の同様のパターン（実際には失敗になることを確認済み）もあわせて参考にしてください。

### チャレンジ認証（認証画面が表示されるパターン）のテスト

カード名義人を以下の値に設定すると、決済時に3Dセキュアの認証画面（パスワード入力画面）に遷移するようになります。
認証画面で入力する**パスワード**の値によって、認証結果を制御できます。

| ブランド | カード名義人 | 入力するパスワード | 結果 |
| --- | --- | --- | --- |
| VISA | BAVCA | 14012 | 認証成功 |
| VISA | BAVCA | 14042 | 認証失敗 |
| VISA | BAVCA | 14052 | 認証成功（Attempt扱い。「与信あり要注意時の続行可否」設定に依存） |
| MasterCard | BAMCA | 15012 | 認証成功 |
| MasterCard | BAMCA | 15042 | 認証失敗 |
| MasterCard | BAMCA | 15052 | 認証成功（Attempt扱い。「与信あり要注意時の続行可否」設定に依存） |
| JCB | BAJCA | 13512 | 認証成功 |
| JCB | BAJCA | 13542 | 認証失敗 |
| JCB | BAJCA | 13552 | 認証成功（Attempt扱い。「与信あり要注意時の続行可否」設定に依存） |
| AMEX | BAACA | 13712 | 認証成功 |
| AMEX | BAACA | 13742 | 認証失敗 |
| AMEX | BAACA | 13752 | 認証成功（Attempt扱い。「与信あり要注意時の続行可否」設定に依存） |

> カード名義人はブランドごとの命名規則（V=VISA、M=MasterCard、J=JCB、A=AMEX）どおり`BAVCA`/`BAMCA`/`BAJCA`/`BAACA`となります。このうちVISA（`BAVCA`）はサンドボックス実機検証で動作を確認済みです。

チャレンジ認証でも、通信エラーのパターンを再現できます。いずれもカード名義人「BAVCA」（VISA）を使い、パスワードだけを変えます。

| パスワード | 再現されるシナリオ | 結果 |
| --- | --- | --- |
| 51001 | 認証サーバー（ActiveServer）からのエラー応答 | 決済失敗（お客様にエラーが表示されます） |
| 30000 | 認証システムでの取引タイムアウト | 決済失敗（お客様にエラーが表示されます） |
| 40000 | 認証システムからの報告電文チェックエラー | 決済失敗（お客様にエラーが表示されます） |

> この3パターンはサンドボックス実機検証で確認済みで、「与信あり要注意時の続行可否」を有効にしていても決済は成功せず、失敗として処理されます（前述の「Attempt扱い」で決済が続行するパターンとは異なります）。テストの際は「決済失敗時にお客様へ正しくエラーが表示されるか」を確認する目的で利用してください。

### このテストで確認できること

- 認証成功時に、通常どおり注文が完了するか
- 認証失敗時に、お客様にきちんとエラーが表示され、注文が正しくキャンセル扱いになるか
- チャレンジ認証で、認証画面（パスワード入力画面）への遷移とサイトへの復帰がスムーズに行われるか
- 「Attempt扱い」となったケースでも決済が進むこと（実際の運用でも、カード発行会社側の対応状況によりこのパターンが発生することがあります）

## 3. テストの記録の残し方

各パターンをテストしたら、[注文の管理](08-order-management.md) で紹介した注文詳細画面の「注文メモ」を確認し、
想定通りの結果（取引ID、エラー内容など）が記録されているかをあわせてチェックしましょう。

## ポイント・注意

- ここで紹介したカード番号・名義人・パスワードは、あくまで試験環境専用のテストデータです。実際のお客様のカード情報とは一切関係ありません。
- 上記の一覧は代表的なパターンの紹介です。より詳細な仕様（デビット・プリペイド判定用のカード番号など）が必要な場合は、ペイジェント社の加盟店管理者サイト（[https://portal.paygent.co.jp/n/manage-m/login.html](https://portal.paygent.co.jp/n/manage-m/login.html)）にログインし、「マニュアル／仕様書 ＞ 試験環境の利用方法」からダウンロードできる「試験環境ツール利用手順書」等の資料もあわせてご確認ください。
- 3Dセキュア2.0は事前申請が完了していないと動作しません。申請状況が不明な場合は、まず [クレジットカード決済の設定](04-credit-card.md) の注意事項を確認してください。
