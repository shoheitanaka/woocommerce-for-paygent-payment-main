# Phase refund — 消込済後の注文操作（返金・キャンセル）＋通知確認

SKILL.md の Phase 0、および [phase-payment.md](phase-payment.md) 1項（消込済まで
到達した注文）の完了が前提。

## 重要な仕様前提（先に理解しておく）

コンビニ決済（番号方式）は**先払い**であり、Paygent側に返金・取消の電文は
存在しない（申込 `030`／照会 `094`／差分照会 `091` のみ。仕様書
`2025docs/コンビニ決済+番号方式.pdf` 参照）。本プラグインの
`WC_Gateway_Paygent_CS` クラスにも `process_refund()` は実装されていない。

**注意（2026-07-29の実機検証で判明・誤解しやすい点）**: `process_refund()`
未実装でも、WooCommerce標準の「払戻額」ボタン自体は注文詳細画面に**表示される**。
これはWooCommerce coreの仕様で、ゲートウェイがオンライン自動返金に対応していなくても
「手動での返金額記録」用のUIは常に表示されるため（クリックすると
「手動で¥Nを返金」という手動記録ボタンになる）。「返金ボタンが出ないこと」を
確認しようとしないこと（出るのが正しい）。実際にPaygent側へ電文が飛ばない
ことこそがこのフェーズで確認すべき点である。

このフェーズで確認するのは、上記前提の下での**手動返金（金額記録のみ）／
手動ステータス変更**とそれに伴う通知・注文メモの挙動。

## 1. 手動返金（「払戻額」→「手動で返金」）

1. 消込済（processing）まで進んだ注文の詳細画面を開き、「払戻額」ボタンで
   返金フォームを開く（全額・部分どちらでもよい）
2. 払戻総額を入力し「手動で¥Nを返金」を実行する
   （**ネイティブ`confirm()`ダイアログが出て自動操作が止まることがある**。
   出た場合はユーザーに手動でOKを押してもらう→sb-ccシリーズの既知の癖と同種）
3. 注文ステータスが自動的に変わること（全額なら「払い戻し」）、
   注文メモに返金記録（返金番号・金額・実行者）が残ることを確認する
4. この操作でPaygentへの電文送信が発生しない（デバッグログに新規の電文が
   記録されない、注文メモにペイジェントからの新規通知が現れない）ことを確認する
   （→ 何もPaygentへ送らないのが正しい挙動）
5. 顧客への通知メール（「払い戻し注文」）が**1通のみ**送信されることを
   WP Mail Loggingで確認する

## 2. 手動ステータス変更（キャンセル）

1. 別の消込済注文で、ステータスをプルダウンから「キャンセル済み」に手動変更する
2. 同様に注文メモ・Paygentへの電文なし・通知メールを確認する

## 3. 消込済後の試験環境ツール操作（非干渉確認・任意）

消込済の決済に対して試験環境ツールで再度ステータス変更を試みると
「更新不可」で拒否されることを確認する（[testtool.md](testtool.md) 参照）。
WooCommerce側の手動ステータス変更とPaygent側の決済ステータスがずれても
システムが混乱しない（エラーや二重処理が起きない）ことの確認が目的。

## 4. 【重要】支払い前（申込済/on-hold）キャンセル後に顧客が支払ってしまうケース

2026-07-29にユーザー指摘・実機検証で確認した既知の問題シナリオ。**Paygent側には
支払い前の申込を無効化する電文が存在しない**（`030`申込／`091`差分照会／`094`照会
のみ。仕様書`2025docs/コンビニ決済+番号方式.pdf`、`system/モジュールタイプ/
02_PG外部インターフェース仕様説明書.pdf`の電文一覧で確認済み）。そのため
ショップ側で「支払い待ち」の注文を先にキャンセルしても、発行済みのお客様番号は
支払期限まで**Paygent側では有効なまま**であり、顧客がそれに気づかず（または
承知の上で）実際にコンビニで支払うと、消込済Webhookが届いて注文が
**キャンセルから処理中へ強制的に巻き戻る**。このフェーズでは必ずこのシナリオを
再現し、巻き戻りの発生と、ショップオーナー向けの警告が実際にはない（通常の
「処理中の注文」メールしか飛ばない）ことを確認する。

1. 新規注文を作成し「支払い待ち」（on-hold）のまま、試験環境ツールでは何も操作しない
2. 管理画面でこの注文をステータス「キャンセル」に手動変更する（決済IDは保存しておく）
3. 試験環境ツールで同じ決済IDを検索し、ステイタスを「消込済」に更新する
   （入金日時=現在時刻、コンビニ企業CD=ローソン）
4. WordPress側で注文を再確認し、以下を確認する:
   - 注文ステータスが「キャンセル」から「処理中」に自動的に巻き戻ること
     （`class-wc-paygent-endpoint.php`の`paygent_update_status_webhook()`は
     `pending/on-hold/processing/completed`の順序しかガードしておらず、
     `cancelled`はこの順序配列に含まれないため後退防止が効かない仕様上の欠陥）
   - 注文メモに「ペイジェントから支払い状況が売上完了:40になっている通知を
     受け取りました」「ステータスをキャンセルから処理中に変更しました」が残ること
   - 顧客には通常の「処理中の注文」メールが送られるが、**ショップオーナー向けに
     この矛盾（キャンセル済みなのに入金された）を知らせる特別な通知は存在しない**
     ことを確認する（＝要改善点。「発見された問題」としてレポートに記載する）

## 5. 記録

各操作を「対象注文・変更前後のステータス・Paygent電文の有無・注文メモ・メール」
の一覧としてレポートに残す。
