# Phase payment — ローソンでの申込〜消込／支払期限切れ＋通知確認

SKILL.md の Phase 0 完了が前提。CS設定 `setting_cs_lm=yes` 必須。
コンビニ選択肢に複数店舗が表示されても、チェックアウトでは必ず**ローソン**を選ぶ。

## 1. 正常系: 申込 → 消込済（入金完了）

Block・クラシックの両方で実施:

1. チェックアウトでコンビニ決済を選択し、コンビニ選択肢から**ローソン**を選択して
   注文確定 → 申込電文（`030`）成功 → 注文ステータスが **on-hold** になること
2. サンクスページ・注文詳細・確認メールに以下が表示されること:
   - お客様番号（`_paygent_receipt_number`）
   - 支払期限日（`_paygent_payment_limit_date`）
   - コンビニ決済案内文（ローソン向けの案内文言。Loppi操作の説明）
   - `receipt_print_url` は表示され**ない**こと（セブンイレブン `00C001` 専用の項目のため）
3. 決済ID（Transaction ID）を [testtool.md](testtool.md) の手順で確認する
4. 試験環境ツールで対象決済を検索 → ステイタスを**消込済**に更新
   （入金日時=現在時刻、コンビニ企業CD=`00C002`）→ 「正常終了しました。」を確認
5. 数秒〜数十秒後、対象注文が自動で **processing** に変わることを確認する
   （Webhookが届いていることの確認。届かない場合はIP許可リストや
   `class-wc-paygent-endpoint.php` のログを疑う）
6. 注文メモに入金確認の記録が追加されていること
7. メール（処理中/完了通知）がWP Mail Loggingで**1通のみ**確認できること

## 2. 異常系: 申込 → 支払期限切れ

いずれか一方のチェックアウト種別で実施:

1. 1と同様に申込 → on-hold の注文を作成する
2. 試験環境ツールで対象決済を検索 → ステイタスを**支払期限切**に更新
   （入力項目なし）→ 「正常終了しました。」を確認
3. 対象注文が自動で **cancelled** に変わることを確認する
4. 注文メモ・メール（キャンセル通知が設定されていれば）を確認する

## 3. 異常系: 申込自体の失敗（電話番号制御値）

いずれか一方のチェックアウト種別で実施:

1. チェックアウトの電話番号欄に `99999999999` を入力してローソンで注文確定
2. 申込電文が異常応答を返し、**顧客にPaygentの実エラーが表示される**こと
   （Block Checkoutで「Something went wrong」にならないこと。既知バグ領域なので
   厳密に確認する）
3. 異常時に注文が作成されない、または作成されてもエラー状態で放置されず
   顧客が再試行できる状態であることを確認する

## 4. 支払い方法の非干渉確認

各注文について、管理画面の注文詳細で支払い方法表示が「コンビニ決済」のまま
（消込済/支払期限切れ更新の前後とも）であることを確認する（→ code-check.md 参照）。

## 5. メール確認

各イベント（申込受付・入金完了・支払期限切れ）後にWP Mail Loggingで、対象イベントの
メールが**各1通のみ**（2重送信・未送信なし）であることを確認して一覧化する。
