# Paygent サンドボックス実決済チェック

コード変更（特に決済フロー・トークン・validate_fields まわり）をマージ/リリースする前に、
サンドボックスで実決済を通して確認するためのチェックリスト。

## 前提条件（先に必ず確認）

1. **送信元IP**: Paygentサンドボックスは送信元IP制限あり。許可外ネットワークからは全電文が
   `P015 IPアドレスが不正です` で拒否される。P015が出たらコードではなくネットワークを疑う。
2. **wp-env 起動**: このマシンでは 8888/8889/8891 は他プロジェクトが占有。

   ```bash
   WP_ENV_PORT=8890 WP_ENV_TESTS_PORT=8892 npx wp-env start
   ```

3. **認証情報**: サンドボックス認証情報（merchant_id / connect_id / connect_password）は
   dev環境（port 8890）のWPオプションに設定済み。tests環境で使う場合はコピーが必要。
4. **接続エラーの切り分け**: `P016`/`curl 60`/`curl 77` はTLS/CAバンドル問題
   （CAバンドルは PEM形式の `curl-ca-bundle.crt` 固定）。決済ロジックのバグではない。
5. wp-env は **http** サイト。外部スクリプトが `https://` 明示になっているか確認
   （プロトコル相対 `//` はポート80解決→約75秒ブロックの原因）。

## チェックリスト

対象ゲートウェイを決めて実施する（CC変更ならCC列、MCCC変更ならMCCC列。共通コード変更なら両方）。
各項目は **クラシックチェックアウトと Block チェックアウトの両方** で確認する。

### A. 新規カード決済

- [ ] 保存OFFで決済成功（注文ステータス・Paygent管理画面で金額確認）
- [ ] 保存ONで決済成功 → マイアカウント「お支払い方法」にカードが表示される
- [ ] Block: 保存チェックボックスがWC Blocksネイティブの1つだけ表示される（二重表示しない）

### B. 保存カード決済

- [ ] クラシック: 保存カード選択＋CVC入力で決済成功
- [ ] Block: ネイティブトークン行（「Visa ending in XXXX」）選択＋CVCで決済成功
      （`wc-{gateway}-payment-token` 経由。validate_fields で弾かれないこと）
- [ ] 無効なトークンID（他ユーザー・他ゲートウェイ）が拒否される

### C. 3Dセキュア 2.0（tds2_check=yes 設定時）

- [ ] 新規カードで3DS2認証画面→決済成功
- [ ] 保存カードで3DS2フロー→決済成功
- [ ] 3DS2キャンセル/失敗時にエラーメッセージが表示され注文が進まない

### D. 支払い方法バリエーション（CCのみ）

- [ ] 分割払い・ボーナス・リボ（設定で有効な方式）で決済成功

### E. カード削除・非干渉

- [ ] マイアカウントからカード削除→Paygent側の顧客カードも削除される
- [ ] 他ゲートウェイ（CC⇔MCCC）のトークン削除が互いに干渉しない

### F. 注文操作（管理画面）

- [ ] 売上（キャプチャ）: 022 成功
- [ ] 金額変更: 028/029 成功
- [ ] オーソリキャンセル: 021 成功
- [ ] 返金: process_refund 成功（部分返金の可否は決済手段の仕様に従う）

### G. 自動テスト

```bash
composer test:sandbox                # サンドボックス通信テスト（許可IPから）
npm run e2e:block-cc                 # Block CC ゲストフロー
npm run e2e:block-cc:member         # Block CC 会員・保存カードフロー
```

- [ ] 上記すべてパス

## 注意事項

- PayPayフルフロー（ログイン〜支払い完了）はサンドボックスのリダイレクトに2〜5分かかるため
  自動テスト対象外。手動確認のみ（`npm run e2e:paypay` は外部遷移確認まで）。
- E2E Webhookテスト用mu-plugin `paygent-test-ip.php` を使ったら、終了後に必ず除去する:

  ```bash
  npx wp-env run tests-cli rm /var/www/html/wp-content/mu-plugins/paygent-test-ip.php
  ```

  （残置すると `WebhookEndpointTest` の403/400期待テストが失敗する）

## 結果報告フォーマット

実施後、以下の形式でユーザーに報告する:

- 実施項目と結果（A〜Gをパス/失敗/対象外で一覧化）
- 失敗した項目は、レスポンスコード（P0xx等）・注文番号・デバッグログの該当行を添える
- 未実施項目と理由（IP制限・環境未設定など）
