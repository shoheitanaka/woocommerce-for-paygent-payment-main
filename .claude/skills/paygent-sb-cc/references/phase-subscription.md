# Phase subscription — 定期購入の決済・強制継続・一時停止/キャンセル

依頼項目6〜7に対応。SKILL.md の Phase 0 完了が前提。
WooCommerce Subscriptions有効時はCCが `WC_Gateway_Paygent_Addon_CC` に自動切替される。
試験環境の既存の定期購入商品を使う（なければ停止して報告）。

## 1. 定期購入の決済処理（依頼項目6前半）

Block・クラシックの両方で実施:

1. 定期購入商品をカートに入れ、新規カード＋名義人 `BAVYA` で3DS2決済 → 成功
2. 確認: 親注文ステータス／定期購入（subscription）が「有効」で作成される／
   注文メタに `fingerprint`（カード識別子）が保存される（debugログまたは注文メモ）／
   支払い方法が「クレジットカード決済」のまま
3. チャレンジ経由（`BAVCA`＋`14012`）でも1回成功を確認
4. メール: 新規注文・定期購入関連メールが各1通のみ

## 2. 手動による強制継続決済（依頼項目6後半）

管理画面→定期購入→対象subscriptionを開き、注文アクションから実行:

1. 「更新を処理（Process renewal）」を実行 → 更新注文が作成され、保存された
   fingerprintで**3DS2認証なしの自動決済**が成功すること
2. 更新注文のステータス・注文メモのPaygent応答・金額を確認
3. 「保留中の更新注文を作成（Create pending renewal order）」がある場合は挙動を記録
4. メール: 更新注文の処理中/完了メールが各1通のみ・親注文のメールが再送されないこと

## 3. 一時停止・再開・キャンセル（依頼項目7）

**管理画面から**（定期購入編集画面のステータス変更）:

| 操作 | 期待 |
| --- | --- |
| 有効→保留（一時停止） | ステータス反映・エラーなし |
| 保留→有効（再開） | 再開後に「更新を処理」で決済が通ること |
| 有効→キャンセル | ステータス反映・以後更新されない |

**マイアカウントから**（マイアカウント→定期購入→詳細）:

| 操作 | 期待 |
| --- | --- |
| 一時停止（表示されている場合） | 顧客操作で保留になる |
| 再開 | 顧客操作で有効に戻る |
| キャンセル | 顧客操作でキャンセルされる |

- Subscriptions設定（WooCommerce→設定→定期購入）で顧客操作の許可状態を先に確認し、
  ボタンが出ない場合は設定値とともに記録する。
- キャンセル済みsubscriptionで「更新を処理」が実行できない（またはエラーになる）ことを確認。
- 各操作のメール（一時停止・キャンセル通知）が各1通のみであることをWP Mail Loggingで確認。

## 4. 後始末

このフェーズで作成したsubscriptionは、最後にすべてキャンセル状態にしておく
（放置すると自動更新が走り、以後の試験のメール判定を汚すため）。
