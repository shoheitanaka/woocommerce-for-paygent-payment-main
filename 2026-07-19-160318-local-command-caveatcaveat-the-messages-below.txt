  3. コードレビュー指摘

  【要修正】MCCC Block の supports 宣言が過剰
  WC_Paygent_Block_MCCC が WC_Paygent_Block_CC::get_supported_features()
  をそのまま継承しているため、Block側は subscriptions
  系9機能を宣言していますが、クラシック側の MCCC ゲートウェイは products, 
  refunds, tokenization のみ対応です（class-wc-gateway-paygent-mccc.php:133）。c
  lass-wc-paygent-block-mccc.php に get_supported_features()
  をオーバーライドして array( 'products', 'refunds', 'tokenization' )
  を返すべきです。WCS有効時はサーバー側で除外されるため実害は限定的ですが、メタ
  データ不整合です。

  【要検討】MCCC の保存カードUIが機能していない（既存問題の顕在化）
  - Block JSは paygent_save_card_info を送りますが、MCCCゲートウェイはこのキーを
  参照せず、store_card_info=yes＋ログイン時はユーザーの選択に関係なく常にPaygent
  側へカード保存します（class-wc-gateway-paygent-mccc.php:396）
  - 保存トークンは paygent_cc インスタンス経由の add_stored_user_data() で
  gateway_id='paygent_cc' として保存されるため、MCCC Blockの
  get_customer_tokens( $user_id, 'paygent_mccc' ) は常に空 → savedCards
  UIは表示されない
  - クラシックチェックアウトも同挙動の既存問題ですが、Blockでは
  enableSaveCard=true
  で保存チェックボックスが出る分ミスリードです。別issueとして切り出すことを推奨

  【軽微・既存】
  - class-wc-gateway-paygent-mccc.php:763 に未定義変数 $test（PHP 8でWarning）
  - PHP 8.2+ の dynamic property deprecation が2件ログに出ます（WC_Gateway_Payge
  nt_CC::$testmode、WC_Gateway_Paygent_ATM::$order_received_text）

  【問題なし】 CS/MB/Paidy のBlock実装はキー・店舗ID・キャリアIDともクラシック実
  装と完全に整合。楽天ペイの272取消/271売上への修正・部分返金ガードも仕様どおり
  で、woocommerce_order_status_completed フックには支払方法ガードあり。

  なお、検証用に起動した wp-env はポート競合回避のため
  http://localhost:8890（tests: 8892）で稼働中です。
